# Usage

```
bower --book <DIR> push [--repo <NAME>] [-o|--out <DIR>] [--site <DIR>] [--execute]
```

Without `--execute` it prints
`dry run   nothing was sent; pass --execute to publish` and returns.

# The guard rail

Generated repositories are force-pushed as a matter of course — they are build
artifacts. That makes "which repository am I about to overwrite?" a safety
question, and the answer is a marker file.

`marker_verdict` decides:

| Remote state | Verdict |
|---|---|
| Absent or empty | `SafeNew` |
| Has content, and its `STEPS.md` names **this** book | `SafeOurs` |
| Has content, and its `STEPS.md` names a **different** book | `Refuse` — "Two books are configured to publish to one repository; fix the `github` key in one of them." |
| Has content, with **no** marker | `Refuse` — "…was not generated by this tool. Refusing to force-push over it." |

**There is no override.** No flag, no environment variable, no config key. To
adopt an existing repository, push a `STEPS.md` to it by hand first.

The marker writer and reader (`marker_line` / `book_named_in`) are deliberately
one pair in `trailers.rs`, so the format cannot drift between what is written
and what is checked.

# Order of operations

Under `--execute`:

1. Create the remote repository, if needed.
2. Push the code and tags.
3. Publish the site to `site_branch`, then enable Pages **only if the branch was
   created this run**.
4. Create the release **last** — *"because a release pointing at a tag nobody
   can fetch is worse than no release."*

# Half-configured is an error, not a silence

| `version` | `assets` | Result |
|---|---|---|
| absent | absent | No release. |
| present | absent | No release. |
| absent | present | **Blocked** — "declares `assets`, but the book declares no `version`". |
| present | present | Release from every `.pdf`/`.epub` **directly inside** the directory. |

Not recursive, deliberately: the renderers' own scratch folders live under the
same roof. An assets directory holding neither format is Blocked, with the exact
render commands to run.

`release_tag(v)` prefixes `v` only when the version is all digits and dots, so a
version like `2e` stays `2e`.

The site is likewise Blocked when it was never rendered or is
[stale](/commands/status.md) — you cannot publish a site that is out of date.

# `PushPlan`

`NotConfigured { repo }` (no `github` key — it says the book does not publish
that repo and never dials out) | `Blocked { repo, reason }` |
`Ready { repo, remote, branch, tags, create, site, release }`.

# Known gaps

`GitHubForge` is untested — releases included — and has already cost two real
defects. The push gate identifies a book by directory basename. `push` also
ignores lock drift. All three are open items in `docs/TECHNICAL_DEBT.md`.
